# CLAUDE.md — Hello Hilary

## What This App Is

Hello Hilary is a private family media platform built for Hilary, an adult woman with severe cognitive and physical disabilities. Her family and care workers upload videos and photos for her to enjoy in a safe, curated environment. The app is intentionally private — invite-only, no public access, no self-registration.

This document is the authoritative spec for all development decisions. Read it fully before touching any file.

## Auth Implementation Spec

### Library Choices
- **Password hashing**: `bcrypt` (bcryptjs for pure JS)
- **Tokens**: `jsonwebtoken` — issue JWTs on login
- **Token storage**: `httpOnly` cookie (not localStorage) — more secure, immune to XSS
- **Session duration**: 30 days
- **Token invalidation**: Sessions table — when admin modifies a user account, delete all rows in `sessions` for that `user_id`. On every authenticated request, verify the token exists in the sessions table in addition to JWT signature verification.

### Login Flow
1. User POSTs `{ email, password }` to `POST /api/auth/login`
2. Server looks up user by email, checks `is_enabled = true`
3. Server compares password with `bcrypt.compare`
4. On success: generate JWT, insert row into `sessions` table, set `httpOnly` cookie
5. Log event to `activity_logs`: `event_type: 'login'`
6. Return `{ id, email, display_name, role }` — no password hash, no token in response body

### Logout Flow
1. User POSTs to `POST /api/auth/logout`
2. Server deletes the session row from `sessions` table
3. Server clears the cookie
4. Log event: `event_type: 'logout'`

### Auth Middleware (`server/middleware/auth.js`)
Create two middleware functions:

**`requireAuth`** — any logged-in user:
- Read JWT from httpOnly cookie
- Verify signature
- Look up token hash in `sessions` table — if not found, reject (handles invalidation)
- Check `is_enabled = true` on the user
- Attach `req.user = { id, email, display_name, role }` to the request
- On failure: return `401`

**`requireAdmin`** — admin only:
- Run `requireAuth` first
- Check `req.user.role === 'admin'`
- On failure: return `403`

### Brute Force Protection
- Track failed login attempts in memory (or Redis if available — memory is fine at this scale)
- After 5 failed attempts from the same IP: exponential backoff (delay responses)
- After 10 failed attempts: send email alert to sheila@hello-hilary.com
- Log every failed attempt: `event_type: 'login_failed'`

### Password Reset Flow (implement after core auth is working)
- Admin can trigger a password reset for any user from the admin panel
- Generates a signed reset token, emails a link to the user
- Link expires in 1 hour
- On use: update `password_hash`, invalidate all sessions for that user

### Remove UPLOAD_CODE
- Delete `UPLOAD_CODE` from `.env` and `.env.example`
- Remove all references to it in the login route
- The login route is being completely replaced

## Route Protection Map

### Backend — apply middleware to these routes:

| Route | Middleware | Notes |
|---|---|---|
| `POST /api/auth/login` | none | Public |
| `POST /api/auth/logout` | `requireAuth` | Must be logged in to log out |
| `GET /api/media` | `requireAuth` | All logged-in users |
| `POST /api/media/complete` | `requireAuth` | All logged-in users |
| `POST /api/s3/presign-upload` | `requireAuth` | All logged-in users |
| `GET /api/s3/presign-download` | `requireAuth` | All logged-in users |
| `PATCH /api/media/:id` | `requireAuth` | Ownership check inside handler |
| `DELETE /api/media/:id` | `requireAuth` | Ownership check inside handler |
| `POST /api/media/:id/processed` | `requireAuth` | Internal but protect anyway |
| `POST /api/media/:id/failed` | `requireAuth` | Internal but protect anyway |

### Ownership check logic for PATCH and DELETE:
```javascript
// Inside the handler, after requireAuth runs:
const isOwner = media.user_id === req.user.id;
const isAdmin = req.user.role === 'admin';
if (!isOwner && !isAdmin) return res.status(403).json({ error: 'Forbidden' });
```

### Frontend — React Router guard components:

Create two guard components:

**`RequireAuth`** (`src/components/RequireAuth.jsx`):
- Checks auth context for current user
- If not authenticated: redirect to `/signin`
- If authenticated: render `<Outlet />`

**`RequireAdmin`** (`src/components/RequireAdmin.jsx`):
- Checks auth context for current user AND role
- If not authenticated: redirect to `/signin`
- If authenticated but not admin: redirect to `/gallery` (or show 403 page)
- If admin: render `<Outlet />`

## S3 File Type Validation

In `server/routes/s3.js`, the `presign-upload` endpoint must validate file type BEFORE issuing a presigned URL.

### Allowed types:
```javascript
const ALLOWED_MIME_TYPES = {
  // Video
  'video/mp4': true,
  'video/quicktime': true,   // .mov
  'video/x-msvideo': true,   // .avi
  'video/x-matroska': true,  // .mkv
  'video/webm': true,
  // Photo
  'image/jpeg': true,
  'image/png': true,
  'image/heic': true,
  'image/heif': true,
  'image/gif': true,
  'image/webp': true,
};
```

### Validation logic:
- Check `contentType` against the allowlist
- If not in list: return `400 { error: 'File type not allowed' }`
- Do NOT trust the file extension alone — trust the `contentType` sent by the client, and note this is still client-provided. For true security, a server-side magic-bytes check after upload is ideal but out of scope for this milestone.

## Logging

Log to the `activity_logs` table. Create a helper: `server/lib/logger.js`

```javascript
// Usage:
await logEvent({ userId, eventType, metadata, ipAddress, req });
```

### Events to log:

| event_type | When | metadata |
|---|---|---|
| `login` | Successful login | `{ email }` |
| `login_failed` | Failed login attempt | `{ email, reason }` |
| `logout` | User logs out | `{}` |
| `media_upload` | Upload completed | `{ mediaId, mediaType, title }` |
| `media_delete` | Media deleted | `{ mediaId, title, deletedBy }` |
| `media_edit` | Media edited | `{ mediaId, fields_changed }` |
| `media_view` | Presigned download URL issued | `{ mediaId, mediaType }` |
| `brute_force_alert` | 10+ failed attempts from IP | `{ ip, attemptCount }` |
| `user_created` | Admin creates a user | `{ newUserId, role }` |
| `user_modified` | Admin modifies a user | `{ targetUserId, fields_changed }` |
| `user_deleted` | Admin deletes a user | `{ targetUserId }` |
| `session_invalidated` | Admin action forces logout | `{ targetUserId }` |
